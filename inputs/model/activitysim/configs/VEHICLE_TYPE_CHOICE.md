# Vehicle Type Choice — PSRC soundcast configuration

This document describes the `vehicle_type_choice` model as configured in this branch
(`asim_veh_choice`), the assumptions made, the data sources, every parameter changed,
and the results observed on the test sample. It is intended for the modeling team
(Brice / Stefan) as the basis for a future formal estimation.

> **Status:** Runs end-to-end on the test sample; produces a behaviorally plausible fleet.
> Coefficients are **hand-tuned, not formally estimated** — they must be calibrated/estimated
> before production use.

---

## 1. What was added to the pipeline

Files added to `inputs/model/activitysim/configs/`:

| File | Role | Source |
|---|---|---|
| `vehicle_type_choice.yaml` | Model settings | PSRC (Mohammad), based on the MTC prototype yaml; PSRC values for `MSA_POP`, `CHARGERS_PER_CAP` |
| `vehicle_type_data_2026.csv` | Alternatives data (makes/models, MPG, Range, price, op cost) | Built from EPA fuel-economy data via `generator.ipynb` |
| `seattle_vehicle_type_choice.csv` | Utility specification (SPEC) | Pre-existing PSRC draft (repo, Apr 2026); range term modified here |
| `seattle_vehicle_type_choice_coefficients.csv` | Coefficients | Pre-existing PSRC draft; `coef_crange` changed, `asc_hyb` added |
| `seattle_vehicle_type_choice_preprocessor.csv` | Chooser preprocessor | Pre-existing PSRC draft |

Changes to `settings.yaml`:
- Added `vehicle_type_choice` to the `models:` list, **immediately after `workplace_location`**.
- Added `vehicles` to `output_tables`.

### Critical ordering requirement
The preprocessor needs `persons.distance_to_work`, which soundcast only creates during the
`workplace_location` step. (In the MTC example, workplace location runs *before* auto ownership;
in soundcast it runs *after*.) Therefore `vehicle_type_choice` must run **after `workplace_location`**.
Placing it right after `auto_ownership_simulate` fails with `KeyError: distance_to_work`.

### Files evaluated but NOT used (intentionally not committed)
- `vehicle_type_choice_op4.csv`, `..._op4_coefficients.csv`, `..._annotate_choosers_preprocessor.csv`
  — the generic MTC op4 specification (available in `prototype_mtc_extended`). Produced a degenerate
  ~100% EV fleet (see §4); superseded by the Seattle spec.
- `vehicle_type_data_2026_rangefix.csv` — a data experiment (see §5a); not used by the final config.

## 3. Data and assumptions (`vehicle_type_data_2026.csv`)

Generated by `generator.ipynb` from the EPA fuel-economy dataset
(`https://www.fueleconomy.gov/feg/epadata/vehicles.csv.zip`):

- **Alternatives:** 5 body types × 5 fuel types × 20 model years (2007–2026) = 500 rows.
- **Body types:** Car, SUV, Van, Pickup, Motorcycle (mapped from EPA `VClass`).
- **Fuel types:** Gas, Diesel, Hybrid, BEV, PEV (mapped from EPA `atvType` + `fuelType1`).
- **MPG, NumMakes, NumModels, co2gpm:** EPA group means by (year, body, fuel).
- **NewPrice:** assumed base price by body type (Car 35k, SUV 45k, Van 40k, Pickup 50k,
  Motorcycle 15k) × fuel multiplier (Gas 1.0, Diesel 1.1, Hybrid 1.15, PEV 1.25, BEV 1.4),
  depreciated 5%/year from 2026.
- **auto_operating_cost:** estimated from MPG (electricity basis for BEV, $3.50/gal basis otherwise).
- **Imputation:** combos with no EPA data are filled using the gas baseline × a fuel ratio;
  remaining gaps set to 0. (Note: this fills many older electric rows' Range with 0 — see §4.)

### Verified EPA fact about `Range`
Checked directly against the raw EPA file (49,927 vehicles):

| Fuel | Rows | Rows with `range` > 0 | Mean `range` |
|---|---|---|---|
| Gas | 44,809 | 0 | 0 |
| Diesel | 1,310 | 0 | 0 |
| Hybrid | 1,805 | 0 | 0 |
| BEV | 1,457 | all | 271 (electric range) |
| PEV | 442 | all | 435 (total range) |

**EPA records `range = 0` (literal zero) for all gasoline/diesel/hybrid vehicles** — it only
computes a range for plug-in vehicles. For BEVs `range` is the electric driving range
(~270 mi); for plug-in hybrids (PEV) it is the **total** gas+electric range (~435 mi). The two
are not the same quantity, which is why raw PEV range > BEV range.

## 4. Problem observed: degenerate ~100% EV fleet

Both op4 and the unmodified Seattle spec produced an unrealistic, almost entirely plug-in fleet:

| Fuel | op4 | Seattle (unmodified) |
|---|---|---|
| Gas | 0.2% | 2.1% |
| PEV | 99.5% | 94.2% |
| EV share | 99.7% | 97.3% |

**Root cause:** the utility term `coef_crange × Range`, applied to **all** alternatives with a
positive coefficient. Because EPA `Range` is 0 for all non-plug-in vehicles (§3), only electric
vehicles received any "range" utility. The coefficient (`0.018`) was also calibrated for a much
smaller range scale, so the term dominated. (op4 additionally adds ~+2.1 utility to every EV via
its large charger-density term.)

---

## 5. Fix

### 5a. Data experiment (diagnostic only — not used)
Filled `Range` with realistic total range for all fuels (`MPG × fuel-tank gallons`; tank
assumptions Car 13.2, SUV 18, Van 21, Pickup 26, Motorcycle 4). EV share dropped 97% → 5.5%,
**confirming Range was the driver** — but pickups/vans (huge tanks → ~600 mi range) became
over-selected, proving `coef_crange` is mis-scaled at any realistic range. Data fix alone is
insufficient.

### 5b. Specification fix (used here)
In `seattle_vehicle_type_choice.csv` / `_coefficients.csv`:

| Change | Before | After | Why |
|---|---|---|---|
| Range term scope | `@df.Range` (all alts) | `@df.Range * (df.fuel_type == 'BEV')` | Matches its documented "Range for BEV" intent (electric range / range anxiety) |
| `coef_crange` | 0.018 | 0.004 | Sized for actual BEV electric range (~270 mi) |
| `asc_hyb` | (none) | -0.8 | New Hybrid constant; prevents hybrid over-selection |
| Data file | rangefix experiment | original `vehicle_type_data_2026.csv` | ICE-range patch unnecessary once range is BEV-only |

## 6. Results (test sample, 37,315 vehicles)

| Fuel | op4 | Seattle | Range-data-fix | **Final (this branch)** |
|---|---|---|---|---|
| Gas | 0.2% | 2.1% | 19.5% | **83.0%** |
| Diesel | 0% | 0.2% | 16.6% | 5.7% |
| Hybrid | 0% | 0.4% | 58.4% | 5.7% |
| BEV | 0.3% | 3.1% | 0.0% | 3.9% |
| PEV | 99.5% | 94.2% | 5.5% | 1.8% |
| **EV share** | 99.7% | 97.3% | 5.5% | **5.7%** |

Final body type: Car 60.8%, SUV 24.3%, Pickup 6.3%, Van 5.4%, Motorcycle 3.2%.
Full pipeline runtime: ~5.5 min on the test data.

## 7. Remaining work (for formal estimation/calibration)

1. **Vehicle age** skews old (median 15 yr) — the Seattle spec has no age constants to offset the
   price terms. Add age ASCs (op4 has `coef_age2…20`) or an age penalty; target ~10–12 yr median.
2. **Formal estimation / calibration** of all coefficients (ASCs, `coef_crange`, etc.) to a PSRC /
   Washington target (e.g. DOL registration shares). ActivitySim's estimation framework can be used;
   the vehicle alternatives data must be included in the estimation dataset.
3. **MPG vs MPGe** — the `MPG` column mixes real MPG (ICE) and MPGe (BEV ~67–96). Put on a common
   basis (e.g. energy cost per mile) or segment `coef_mpg` by fuel.
4. **`CHARGERS_PER_CAP` / charger term** — if returning to op4, treat its very large coefficient
   (1686.87) and the charger value as a deliberate calibration target.

uv run python -m activitysim run ^
  -c <soundcast>\inputs\model\activitysim\configs ^
  -d <asim_data_test> ^
  -o <output>

exclusion for the uv Python interpreter (see project notes).
